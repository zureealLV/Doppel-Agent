# Doppel Agent v0.14.0 发布证据与下一阶段

## 本轮目标

这一版不继续堆框架名，而是验证 Agent 运行时遇到外部故障时是否能明确收敛。新增 `bench/fault_matrix.py`，以固定本地 transport、进程内 MCP fixture、SQLite 和真实子进程执行 10 个可重复场景；每个场景保留注入故障、预期策略、原始观察值、通过位和失败原因。

## 生产路径修复

### Provider half-open 单探针

`AsyncOpenAICompatibleProvider` 的 circuit breaker 现在使用异步锁保护状态。达到 reset window 后只有一个请求取得 half-open probe，其他并发请求继续收到 `ProviderCircuitOpen`；probe 成功才清零错误计数，失败则重新进入 cooldown。取消 probe 会释放槽位，但不会把用户取消误记成上游失败。

### MCP schema cache 与连接代际绑定

`MCPClientManager` 每次成功建立 session 都递增 server generation。`MCPToolCatalog` 的 cache key 同时比较服务元数据与 generation，因此 stdio 进程退出或 Streamable HTTP 重连后，即使 server version 没变，也会重新拉取工具 schema。有副作用的 `call_tool` 遇到“请求可能已被服务端接受”的模糊断连仍只调用一次，不自动制造重复副作用。

### 重启 lease 原子收敛

`RunService.start()` 在接受新任务前调用 `RuntimeRunStore.recover_incomplete()`。同一 SQLite 事务内，遗留 `queued`/`running` 记录被更新为 `failed`，写入 `finished_at` 和 `service restarted before completion`，并追加 `run.recovered_after_restart` 事件。客户端不再看到永久卡住的非终态，SSE 可从旧 `after_seq` 继续读取恢复事件。

## 固定故障矩阵

提交报告：[`bench/reports/2026-09-22-v0.14.0-fault-matrix.json`](../../bench/reports/2026-09-22-v0.14.0-fault-matrix.json)

| 类别 | 场景 | 结果 |
|---|---|---|
| Provider | 429 + Retry-After | 2 次调用；精确记录 0.125 秒请求延迟 |
| Provider | connection refused | 2 次总尝试后明确失败 |
| Provider | read timeout | 2 次总尝试后明确失败 |
| Provider | HTTP 503 | 有界重试并保留 503 终态 |
| Provider | half-open concurrent demand | 仅 1 个 probe 穿透，恢复后成功 |
| MCP | side effect 后模糊断连 | remote call=1，不自动重试 |
| MCP | 同版本 session 重连、schema 改变 | 建立 2 个 session，schema hash 更新 |
| SSE | 慢消费者从 `after_seq=1` 恢复 | streamed IDs 与 durable IDs 均为 2/3/4 |
| Runtime | 重启丢失 queued/running lease | 2 条记录均进入 failed 且有恢复事件 |
| Command | 0.1 秒超时 | 明确 timeout，active process registry=0 |

总分母 `10`，通过 `10`，失败 `0`。这是离线系统可靠性证据：Provider/MCP 是固定替身，不能外推成真实网络可用性或模型质量。父进程派生子进程后的取消清理由独立 integration test 覆盖。

## 已知边界

- 故障矩阵没有调用付费模型，也没有给三运行时填写质量分；v0.12 的 180-run Mock 结果仍只是 plumbing smoke。
- Streamable HTTP 的真实网络抖动、第三方 MCP server 崩溃和 Provider 区域性限流仍需在可控测试环境另跑，不能从固定 fixture 直接外推。
- Vue Runtime Workbench 尚未覆盖旧首页的持久对话、Provider/DPAPI 设置、搜索与归档，因此旧页继续保留。
