# Doppel Agent v0.13.0 发布证据与下一阶段

## 本版目标

把 v0.12 已稳定的 FastAPI、LangGraph/DeepAgent、Skill、MCP、补丁、审批和异步子 Agent 能力做成一个可演示、可追踪、可继续扩展的面试项目界面，而不是只留在接口和测试代码里。

## 技术栈

- 后端：Python 3.11、FastAPI、LangGraph、Deep Agents、MCP Python SDK、SQLite WAL。
- 前端：Vue 3.5.43、TypeScript 5.9.3、Vite 7.3.6、Lucide Vue Next 0.577.0。
- 测试/构建：pytest、Ruff、Vitest 3.2.7、vue-tsc 3.3.11、PyInstaller 6.22.3。
- CI：GitHub Actions checkout/setup-python/setup-node v7；Node 24；Python 3.11/3.12 matrix。

## 可核验交付

1. `/runtime/` 提供 Vue Runtime Workbench；旧 `/` 对话工作台仍在，且新增 Runtime Lab 入口。
2. 可创建 `legacy`、`graph`、`deep` 运行并按次授予 workspace write、command、MCP、delegate。
3. durable SSE 以 `after_seq` 续传；前端解析命名 SSE 帧并用普通事件查询补偿断线。
4. 时间线区分 lifecycle、Graph/checkpoint、Skill、MCP、subagent、patch/verification。
5. interrupt 支持 approve/reject/edit；Diff 来自真实 `_doppel_patch.unified_diff`，不根据提示词伪造。
6. 子 Agent 可创建、查询、追问、取消；服务端继续强制只读、禁止递归委派。
7. Vite bundle 随 wheel 和 PyInstaller onedir 打包；`/runtime/assets/*` 在 URL decode 后做根目录 containment 检查。

## 本版刻意没有宣称

- 旧对话、模型设置、全局搜索尚未全部重写为 Vue；并行页面不是“全量迁移完成”。
- 180-run Mock smoke 仍只证明 plumbing；没有真实模型成功率。
- 异步子 Agent 是同进程有界任务，不是分布式 worker 集群。
- Job Object 管进程树生命周期，不是 Windows 权限沙箱。

## v0.14 计划：故障恢复与真实评测执行器

### 1. 故障注入矩阵

- Provider：429 + `Retry-After`、连接拒绝、read timeout、5xx、半开 circuit breaker。
- MCP：stdio 进程退出、Streamable HTTP 断连、schema cache 失效、有副作用调用后的模糊失败。
- SSE/API：慢消费者、连接中断后 `after_seq` 补发、服务重启后的 running/queued lease 收敛。
- 命令：父进程拉起子孙进程后取消/超时，记录 Job Object 或 fallback 的真实路径。

验收：每个场景有固定 fixture、明确 terminal status、无重复副作用、事件序号连续，报告保留分母和原始失败原因。

### 2. 真实模型矩阵执行器

- 复用 20 case × 3 runtime × 3 repeat 协议，但增加逐 case scorer、人工复核队列、Token/费用/耗时和失败分类。
- 同一模型、温度、Provider、代码快照与时间窗口对照；不可将 Mock、不同模型或未判定答案混入成功率。
- 先跑小规模 canary，再运行完整 180 次，避免配置错误直接消耗额度。

验收：每个 run 有输入快照、runtime、模型、usage、原始答案、工具轨迹、判定与复核人；汇总能追溯到每个分子/分母。

### 3. Vue parity 决策

- 补齐 provider profiles、DPAPI key 状态、持久对话/搜索/归档和旧审批入口。
- 完成 parity checklist 后才把 `/runtime/` 提升为默认首页；否则继续并行，禁止为了“统一技术栈”删除稳定功能。

### 4. v1.0 发布门禁

- Python/frontend/Windows 三类 CI 全绿；wheel、sdist、onedir 均从干净 checkout 构建。
- 远端 main SHA 与 tag SHA 一致；GitHub Actions 对分支和标签都成功。
- README 只保留已测能力、明确安全边界；真实模型指标必须附协议、日期、模型和分母。
