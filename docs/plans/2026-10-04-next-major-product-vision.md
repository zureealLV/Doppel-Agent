### 4.1 核心端到端流程

1. 打开项目 → 选择“修复问题 / 实现功能 / 审查代码 / 添加测试”模板，模板只填输入，不偷发请求。
2. 显式添加文件/行段/约束，预览将发给模型的上下文来源与大小。
3. Graph/Deep 提出计划；用户调整或批准执行范围。计划批准不是写入/命令/MCP 的通用授权。
4. 读取与只读分析可在限额内并行；写入由主 run 通过 Policy Gateway 与锁提交具体 patch。
5. 审查 Diff → approve/edit/reject；基线变更需重新计算并重新批准，拒绝或取消不能暗中落盘。
6. 运行已授权 allowlist 验证，查看真实退出码和日志。
7. 汇总“改了什么、验证了什么、哪些失败/没验证”，生成脱敏交付报告。

### 4.2 工作单 / DAG 契约

工作单是新产品域：`work_order_id`、`plan_revision`、节点 `task_id`、`attempt_id -> run_id`；不是 conversation_id/thread_id 的别名。现有 tasks.sqlite3 的 per-run TaskManager 保留，不直接重定义旧表语义。

新增工作单表优先纳入 runtime.sqlite3，事务只负责创建节点/依赖/dispatch intent，所有实际运行仍交由 RunService/现有 scheduler admission。用唯一 attempt key 与可恢复 dispatch intent 消除重复接收，不承诺外部副作用普遍 exactly-once。

- 计划循环依赖、跨工作单依赖、非法状态迁移拒绝。
- 单节点运行、依赖满足后继续、失败暂停后续、显式重试、全单取消均有持久状态。
- `waiting_approval` 与工具 IO 未 drain 的 run 仍占用既定 owner/lease，不能伪装 idle。
- 修改未开始节点产生 plan_revision；活动节点不能原地改提示/能力。已完成副作用不因重试被重放。
- 先交付串行 DAG 编排；并行只读节点复用现有限额；不新增不受控 agent swarm。

### 4.3 上下文 / 记忆契约

显式附件记录 workspace-relative path、行段、内容 hash、截断原因及接受时快照。文件更新后提示 stale，不悄悄引用旧行号。上下文不包含凭据配置、忽略目录、未授权工作区外文件；不将整个仓库默认上传。

项目笔记与 checkpoint 分开：持久笔记需用户确认，不能自动写全局记忆；历史压缩保留关键约束与完整 tool-call/result 组。UI 分别标注 provider actual usage、估算水位与不可用，不能把估算当精准 tokenizer。

### 4.4 Git / Patch / 验证契约

默认只读 Git 状态和 Diff；读取不执行仓库 hooks、不递归进入任意外部路径。项目无 Git 或 Git 不可用时仍可使用 patch/验证，并给出明确提示。

Agent 改动以接受时 base hash、patch 文件范围和 ledger 为证据；仅靠当前 Git diff 无法断言都是 Agent 生成。逆向撤销是新 patch，检查当前文件仍匹配已应用内容并重新审批，不用 `git reset --hard`，不覆盖用户后续改动。

测试失败不默认自动回滚有效修改；部分应用回滚遵循现有原子 patch 约束。验证必须记录配置版本、argv、cwd、grant、退出码与取消/超时原因，不能把测试命令退出0推广为模型任务成功。

### 4.5 安全、费用与可观测性

所有 runtime/子任务/MCP 都走同一应用权限边界；子 Agent 不继承写、命令和递归委派。stdin/stdio、受限路径和 Job Object 均不构成强 OS sandbox。

Provider 费用展示以实际 usage + 有币种/日期的价格快照计算；缺失时显示未知，不补造0。普通聊天目前没有评测 runner 的共享10CNY预算保证。若本版增加运行/工作单预算，必须统一累计父子调用、控制 admission、缺失 usage sticky-stop；在没有 provider 侧 cap 时只称软件预算防护，不能承诺账户硬封顶。

流式体验先复用 durable SSE 工具/状态事件；若补 token delta，delta 只能是未完成输出，终态回答持久化/投影仍幂等。不要把 SDK 隐藏推理内容当必须展示的“思维链”，只呈现公开计划、动作、结果和简要依据。


- **项目入口**：最近项目和目录选择；一个桌面实例一个活动工作区。首版切换需现有 kernel 正常 drain/释放再启动新 kernel，不做无约束多项目后端池。
- **对话**：回答居中、工具步骤折叠；待审批/失败有显式行动按钮，不强迫读 JSON。
- **计划**：可编辑列表 + 依赖标签 + 当前节点；先列表，非必须画全屏 graph。
- **变更**：文件导航 + unified Diff，宽屏可切 side-by-side；顶部状态区区分 proposed/applied/conflict/verified。
- **验证**：运行/取消按钮、每个检查项状态、日志、失败定位；没有执行的项显示“未验证”。
- **任务**：全局队列、阻塞原因、当前占用/上限和父子任务树；诊断指标按需展开。
- **扩展**：Skill 与 MCP 两个页签；来源、能力风险、validation、显式刷新/probe 清楚可见。
- **设置**：模型连接、项目验证、上下文排除、执行限额、外观/快捷键、诊断导出；不自动 probe 或继承危险 grants。

### 视觉与交互

延续 Codex/Ghostty 式低干扰工作台，但避免照抄。实体深色背景，无透明白边、无大面积渐变/玻璃模糊、无营销 dashboard 卡片墙；青绿作为执行/成功强调，蓝色用于选择，琥珀用于待批准，红色只用于失败/危险。

保留现有 semantic tokens 和系统字体，中文使用 Segoe UI/Microsoft YaHei 回退，代码使用 Cascadia Code/Consolas；首版不下载远程字体。正文14–16px，代码13–14px，清晰行号和折叠层级。状态必须有文字/图标，不只依赖颜色；焦点、键盘与 reduced-motion 可用。

侧栏建议240–280px、Inspector320–480px可调；窄屏折叠为抽屉，不压缩出不可读的常驻三栏。Enter发送、Shift+Enter换行、Ctrl+K搜索保留；Escape只关当前浮层/取消选取，不默默取消后端任务。

## 6. 架构与改造切面

```text
Vue Workbench / Windows Desktop / compatible CLI
                     |
            loopback REST + durable SSE
                     |
        Product services (work orders/context/git/report)
                     |
    RunService -> existing Scheduler + owner/lease + limits
                     |
    Legacy | Focused LangGraph | Deep Agents
                     |
    Policy Gateway -> workspace/patch/verification/Skills/MCP

```

UI 不直接写 SQLite、不直接操控 subprocess；新 API 必须继承 loopback/origin、权限、错误脱敏和受控 IO。Repo 层负责迁移/事务，ProductService 负责跨域编排；避免 route handler、runtime node、UI 各自复制调度逻辑。

## 8. 统一验收：旧门禁 + 新行为

1. **继承 N1–N6**：历史/搜索/归档/删除/配置/键盘/恢复；审批/副作用/冲突/重启/子任务；Skill/MCP；桌面控制/DPI/owner/进程与7库释放；hybrid与Legacy；完整DoD、review、远端精确交付。

3. **上下文**：路径越界、symlink、忽略/secret文件、尺寸上限、stale行段、笔记未确认不注入、不将历史注入两次。
4. **Git与变更**：无Git仓库、用户脏文件、多文件partial失败、base冲突、撤销后用户改动保护、验证超时/取消与所有子进程释放。
5. **UI**：真实EXE常用工作流、焦点/滚动/切页/关闭保存、DPI100/125/150/200按实际可测组合记录；未测试组合不声称通过。宽度375/768/1024/1440的组件/浏览器证据不替代原生DPI。
6. **性能**：先固定fixture与测量方式，报告启动、队列等待、事件积压、UI列表/日志上限、SQLite忙等待和资源峰值；不预填成功率/速度提升。100任务+active4是压力协议/配置，不是模型任务完成率。

## 9. 明确不做

- 不复制 TackleClaude 源码、不认领它的成功率/成本指标。
- 不把本地路径约束或命令白名单宣传为强OS隔离；无真实隔离前不承诺无人监管运行不可信仓库。
- 不开发完整IDE、TUI、多人协作、云账户、浏览器自动操作、向量数据库、市场自动安装或不限额多Agent递归。
- 不自动 Git commit/push/reset、不覆盖真实用户数据、不接管日常 EXE、不默认访问付费服务。
- 不把 Server Mode 作为本版交付条件；测出单机瓶颈后才讨论 PG/Redis、多worker/租户/OAuth。
- 不因技术栈建议而自动升级锁定依赖；新依赖版本在实现阶段明确选择、锁定、打包和验证。

## 10. 官方技术依据（2026-10-04 查阅）

- [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：thread checkpoint 与跨thread store 分工；产品笔记不能混成 checkpoint。

- [Deep Agents overview](https://docs.langchain.com/oss/python/deepagents/overview)：规划/文件系统/子Agent等作为执行器能力，不转移应用所有权。
- [MCP architecture](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture)：host/client/server 分工与传输边界，不把连接器当业务workflow。
- [SQLite WAL](https://sqlite.org/wal.html)：同机共享内存、单writer、checkpoint与备份约束；打包时检查实际SQLite版本/已知修复，不只看Python包版本。
- [pywebview guide](https://pywebview.flowrl.com/guide/)：沿用 web UI + Python desktop host，不因产品化重写桌面壳。
- [Monaco Editor](https://microsoft.github.io/monaco-editor/)：仅备选 Diff/editor 能力，本版首切片不引入。
