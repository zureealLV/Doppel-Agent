## 已实际复现的缺口

### P0-A：unknown usage 只阻止下一 run，不阻止当前 run 的下一模型请求

位置：`bench/live_runtime_matrix.py` 的 `_UsageProvider.next_turn` 和
`execute_runs`。前者只把 `usage_complete=False`；后者直到整条 runtime
返回才判定 cost unknown。工具回合已经先触发下一 HTTP 请求。

复现：第一响应带文件读取 tool call 但不带 usage，第二响应带正常 usage。
Legacy、Graph、Deep **各发出 2 次请求**，最后记录 `completed / usage_unavailable`
并停止 run 序列。run 间止损确实有效，但不满足“未知计费后不再发起请求”。

### P0-B：Deep Provider 失败后 fallback 继续请求

位置：`src/doppel_agent/runtime/deep.py` 的 `run` 广泛异常 fallback，与
评测 `_UsageProvider` 缺少 sticky 请求拦截组合。

复现：固定 HTTP 401。Legacy、Graph 各 **1 次请求**；Deep **2 次请求**，
因为其异常触发 Graph fallback。本轮全部为 localhost 假服务，未产生费用。
应在评测 Provider 边界终止后续请求，不应为了评测直接删掉产品正常 fallback。

### P0-C：无效 usage 和非有限计费参数被接受

位置：`_UsageProvider.next_turn` 用 `isinstance(value, int)`，未排除 bool
和负整数；`execute_runs` 只用 `min(...) <= 0` 检查价格与预算。

- `True/True` 被累计为 **1/1**，`usage_complete=true`。
- 第一 turn `-1/-1`，下一 turn `12/9`，被累计为 **11/8** 且视为完整。
- input price 为 NaN 时 fake runner 调用 **2 次**、cost 非有限；Infinity
  调用 **1 次**、cost 非有限；NaN budget 调用 **2 次**而不在入口拒绝。
- 正常 CLI 的 float 参数同样允许解析这些值。这里测试的是无网络 fake
  runner，不宣称观察到了真实花费超额。

需要严格验证每次 usage，以及所有价格/预算的 finite-positive 条件。

### P1-D：synthetic failure-class 测试通过，不代表实际 HTTP 分类正确

同步 `OpenAICompatibleProvider.next_turn` 把 HTTP 错误转换为普通 RuntimeError；
当前评测分类主要识别 Async Provider 的 typed error。Legacy 又会把异常吞成
failed result，导致来源信息丢失。

实际 HTTP 401 结果：Legacy **runtime_failed**、Graph **internal_error**、
Deep **internal_error**。正确行为应保留 **provider_auth** 且不输出原始异常。
因此这项虽是分类问题，也必须在付费实验之前解决，避免错误解释结果。

## 后续顺序（已写回原计划）

1. **Task 3A–3C**：严格计费输入 → 请求级 sticky 止损 / fallback 拦截 →
   同步 Provider typed failures 与失败耗时。每个修复先红后绿；要求新审计
   六个 gate 全绿。先不要用真实模型“测测看”。
2. 凭据/模型/价格/硬预算齐全后：固定 clean commit，**9 导航 → 人工判定 →
   12 盲审 → 人工判定**，报告 native/fallback 与 false positives。
3. 无凭据时继续离线：**能力矩阵先行**，区别 direct runtime 和 RunService
   能力，显式 unsupported / 分母；再逐题补 13 case 的 fixture/oracle。
4. 所有支持路径和判定冻结后，才跑三重复 full matrix；若未支持全部键，
   不得沿用 180/180 名称或分母。
5. 接回总计划 Vue 完整 parity / Windows 打包与实机视觉 QA / 发布门禁。
   当前无需 Redis/PostgreSQL/新框架；缺的是可信的测试和执行边界。

Windows 打包，不把前端 build 成功包装成这些结果。
